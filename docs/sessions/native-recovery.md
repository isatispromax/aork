# Native Session recovery

`Session` remains the workbench conversation identity. `sessions.recoverNative` takes exactly `{sessionId}`. It creates a new Run, generation, managed process and Workspace Claim, then negotiates stable ACP v1 again. It never adopts an old process or RPC connection. Unknown old writers must first be reconciled through their actual owners; recovery cannot release their Claims. Browser reconnect does not invoke recovery.

Runtime chooses the private saved native ID and state reference. The caller cannot supply either value, an owner, a path or a source Run. The saved Profile revision, Provider definition and owning Plugin version, detected executable version, canonical native state directory and protocol must match. An optional server-only Provider `inspectNativeSession({nativeSessionId,stateDirectory,detectedVersion,signal})` must report available. Missing inspection or unavailable state rejects recovery visibly. Inspection is read-only and bounded to two seconds; Providers must honour cancellation. Profiles independently verifies the restricted directory and binds the prepared launch to its actual current Provider owner.

The new handshake must advertise `loadSession:true` and match the saved Agent identity/version. Only then does Runtime call `session/load` with its private ID and the registered Workspace. It never falls back to `session/new`. Setup failures stop the new managed process; incomplete cleanup retains the new Claim. A user may explicitly choose a new native context through `sessions.startRun`; the default view requires that choice separately. Choosing another Provider still requires a separately configured Session; this command does not transfer native IDs across Providers.

## Replay and retained records

Native replay uses a separate bounded ordered ingestion lane. Text preserves codepoints and long messages split into display entries. Image/audio/resource content uses explicit placeholders without copying binary data or private native locations. Safe tool status reports are display values only; arguments, raw output, titles, locations, thoughts, authentication content and unknown metadata are excluded. Permission/form requests during replay are cancelled and cannot create live Interactions. Unimplemented setup/auth requests remain unsupported.

After the load RPC, all ordered ingestion and the complete negotiated configuration validate successfully, Runtime commits bounded entry facts plus a completion marker together with final Run readiness in one transaction. Stop requests, stopping and Host shutdown prevent this commit. Each fact remains below the Host's 32KiB limit. Sessions stages these in its own tables and switches its active projection only when the completion marker is applied, together with the Sessions event and consumer offset. Failed or interrupted replay preserves the previous visible generation. Late chunks before any subsequent live prompt are ignored. A valid peer must complete its replay before returning the load response; the Host cannot distinguish an unlabelled protocol-violating replay chunk from new output after a later live prompt begins.

The replay budget is 4MiB of serialized visible input, 2,000 visible frames/entries and the existing 1MiB ACP wire-message limit. Exceeding these limits fails visibly and retains the earlier projection. It does not publish a partial/truncated history as complete. Unknown future native content semantics, including compaction capabilities that this client has not negotiated, are not promised.

Workbench inputs, queued Turns, Interactions, interruption records, immutable receipts and Artifact references are independent records. Recovery neither deletes nor rewrites them. Replay emits no Turn completion/reply fact, Host tool execution, Artifact registration or unread activity. Reliable native IDs group replay chunks without guessing from text. Overlong IDs are omitted rather than truncated into false matches. A saved live message ID does not prove that its retained workbench presentation is complete: it may be an interrupted prefix or a compacted window. The default view therefore preserves every complete recovered message in its explicitly separate native group, alongside the original workbench records, even when both groups reference the same ID. It does not suppress native content based on ID presence, Turn completion alone, or text equality.

Recovery preserves `dispatchPaused` and does not resend the last input. Old queued inputs retain their identities/configuration. `sessions.continueQueue` with explicit new-generation consent remains necessary before old queued inputs dispatch.

## Public reads and replaceable views

`GET /api/resources/sessions.nativeHistory?sessionId=<uuid>&after=<offset>&generation=<uuid>` and the same `sessions.nativeHistory` snapshot return an owner-filtered page: Session ID, active generation Run ID, source Run ID, entries and a nullable next offset. The first request may omit the generation; later pages should bind to it. A changed generation returns409 so a reader reloads from the first page. Pages contain at most25 entries and use a 50KiB actual JSON-byte budget beneath the 64KiB resource/snapshot limit. Native history is never appended to the existing bounded live timeline or its actionable Turn IDs.

`aork.sessions.recovery@1` and `aork.sessions.native-history@1` are separate selected views. Default Detail composes them alongside Messages, Tools, Interactions and Composer; Workspace Files remains composed by Workspace. An independently built and installed UI archive replaces these two views through the same public commands and snapshots. No private component imports are needed. The default recovery view retains an uncertain command identity across refresh for immutable receipt retry. Its independent environment observation keeps both recovery and new-context starts disabled while directory observation is unavailable or the registered directory is no longer available. Saved history remains mounted.

Browser Run projections, new Run events and new command results omit the native ID and native state path. `nativeBound` states only that Runtime captured a binding; it is not restoration authority. Existing server-owned bindings remain available for recovery. The `nativeHistory.restorable:false` overview intentionally does not promise an unperformed state check: `check-required` means the explicit recovery command must verify readiness. Old accepted receipts/events are historical values and are not rewritten by this feature.

## Verification boundary

Real local Node24.22.3 Hosts, installed Plugins, SQLite, macOS Runner groups, public HTTP/resources/snapshots/events/receipts and Chromium cover persistent external ACP history, new process/generation, partial/failing replay, ordered final chunks, safe display, cancelled replay requests, byte budgets, native version/state gates, retained input and paused queue, explicit continuation, old protected writers and default/independent UI refresh/mobile. External ACP behavior and fault timing alone are controlled fixtures. This is not real Claude/Codex, Linux, remote deployment or backup/restore acceptance. Actual Tools/Artifact integration and unread behavior require the accepted owning Plugins; their joint evidence is recorded separately rather than inferred from these protocol fixtures.

Protocol primary: [ACP v1 Session setup](https://agentclientprotocol.com/protocol/v1/session-setup). Implementation uses the installed `@agentclientprotocol/sdk@2.7.0` stable v1 declarations and semantics, not the SDK unstable/v2 entrypoints.
