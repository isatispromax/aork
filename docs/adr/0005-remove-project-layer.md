# 移除 Project 组织层，工作区成为顶层组织单位

2026-11-21：决定从领域模型整体移除 Project。Project 曾是纯逻辑组织容器（只有名字，不绑目录），用户被迫先理解「项目 ≠ 目录」两层概念才能开展工作；而 Workspace 本就绑定真实目录、拥有稳定身份，组织职责与文件环境职责合并在一层更自洽。移除后 Workspace 是唯一顶层组织单位，创建时必须通过目录选择器绑定服务器目录；Artifact、Session 等一切归属从 projectId 改为 workspaceId。

考虑过的替代方案：保留 Project 只加目录选择器——留下零信息量的组织壳和两套心智模型；把 Project 降级为标签/分组——概念成本未消除，实现成本反而更高。均拒绝。

后果：升级不迁移数据，schema 直接改历史 migration 声明，已有数据目录作废需清空重建（迁移运行器只允许 CREATE 语句，为一次性 DROP 扩展机制不划算）。产品失去「与代码无关的纯组织容器」能力——若将来出现分组需求，以 Workspace 属性或独立分组机制重新评估，而不是恢复 Project。URL hash 的 `project`/`artifactProject` 键随之消失，公开契约与既有部署校验脚本同步变更。
