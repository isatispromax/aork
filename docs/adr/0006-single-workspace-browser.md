# 左栏为单一工作区浏览器，并移除工作区归档态

2026-11-28：决定把左栏的「工作区」与「会话」两个分区合并为 dsh 形态的单一工作区浏览器，同时从领域模型整体移除工作区归档态。此前工作区分区只列工作区行，会话分区另行按工作区分组，同一工作区在左栏出现两次；dsh 的工作区管理从结构上就是一棵树——工作区行是分组头，会话嵌在下面，折叠、目录树嵌套（子工作区排在父级会话之前）、拖拽落点冒泡到祖先、悬停卡与右键菜单都挂在这棵树上，分区并存时这些行为无法成立。归档态是 dsh 没有的 Aork 自有状态：它保留登记却拒绝新会话与 Run，且没有任何恢复途径，与「删除工作区（仅解除登记）」职责重叠。

合并后 `aork.workspace.navigation@1` 是唯一的浏览分区，仍由 workspace 插件提供：它拥有工具栏（搜索、视图选项、添加工作区）、工作区行及其管理动作。会话行归 sessions 插件，经新的公开视图 `aork.sessions.rows@1` 按分组挂载（未分组为末尾一组）；`aork.sessions.navigation@1` 退役。目录选择器注册为公开视图 `aork.workspace.directory-picker@1`，供新建会话界面的选择器「添加工作区…」使用。这与 ADR-0004 一致：组合只经公开视图契约与公开命令／快照，sessions 插件缺席时浏览器只显示工作区行。

归档态随 `status` 字段与 `workspace.archive` 命令一起删除，`requireOpenWorkspace` 收窄为 `requireWorkspace`（只校验登记存在），会话环境状态相应只剩 `open | unavailable`。管理工作随之对齐 dsh：同一规范目录只登记一次、名称默认取目录名、重命名查重、添加工作区后直接进入该工作区的新建会话；中央的「所有工作区」卡片页与工作区详情页一并移除，未选中会话时中间是新建会话界面。

考虑过的替代方案：保留两个分区、只把工作区行的外观与菜单对齐 dsh——依赖单棵树的行为无法实现，且重复列出的结构问题原样保留；保留归档作为 Aork 扩展——它没有恢复路径、与删除职责重叠，而彻底移除只触及一个状态位与一处校验。均拒绝。

后果：升级不迁移数据，Workspace 记录去掉 `status`、增加 `createdAt`，Session 记录内嵌 Workspace 快照，已有数据目录作废需清空重建。产品失去「保留登记但停止使用」的工作区状态——需要时用删除登记代替：其会话转入「未分组」，重新添加该目录即可在其中继续工作（旧会话留在「未分组」，不随新登记回来）。dsh 首次启动自动创建默认工作区的做法不采用：它与 ADR-0005「创建时必须经目录选择器绑定已有目录」冲突。
