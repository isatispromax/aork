# 全部正常界面通过公开契约替换，宿主只保留最小启动兜底

2026-11-15：用户要求像 dsh 一样所有界面均可由插件定制，包括整体布局、输入、审批表单、登录、设置与插件管理。选择版本化公开 UI 契约：发行 profile 显式选择独占视图提供者，多项扩展按稳定 ID 排序／隐藏，默认 UI 与独立 UI 包遵守同一接口；组合布局保留子界面替换能力，宿主不内置正常业务 UI。

保留固定业务 Shell、仅开放附加面板虽较省开发成本，却不能满足完整定制；任意 DOM／React monkey patch 看似自由，却会把插件绑到私有树结构，使升级、冲突和撤销难以控制。选择公开契约意味着首版就要维护 UI 版本、兼容矩阵、明确选择、错误恢复与跨插件组合验收，接受这项成本以获得可独立安装、替换和维护的界面。

UI 只使用公开数据及 commands；认证、Workspace Claim、运行及 Interaction 规则仍由服务端强制。提供者失效后使用显式兼容回退或最小错误兜底，不能靠最后注册者胜出或另一套宿主固定页面恢复；单个登录／管理 UI 故障不等于认证服务失效，不撤销其他有效登录或自动停止 Run。首版可信同源 UI 仍有页面权限，本决策不构成恶意插件沙箱，也不承诺无停机切换。

本决策补充 ADR-0001／0002，不改变 ADR-0003 的数据所有权；详见[架构基线第 4.4、11 节](/Users/yangdi/code/multai/Aork/.scratch/plugin-ai-workbench/technical-architecture.md)。目前是设计契约，正式实现仍须等待工单 01 用户交互确认，尚未通过插件替换验收。
