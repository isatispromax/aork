# 15: 一次性响应权限请求

**What to build:** 用户在会话中允许或拒绝有效权限请求，多标签页和取消竞争不会重复批准。

**Blocked by:** 12: 完成文本执行轮次并随时取消

**Status:** ready-for-agent

- [ ] Interactions 持久化请求投影，从 Runtime 事实更新状态；提供会话卡片、查询和响应命令，不把活 RPC 句柄存成可跨连接复活的请求。
- [ ] 原子领取响应后，Runtime 再核对 run、generation 和活句柄；两标签页仅一次成功。
- [ ] 取消先封闭响应通道，旧连接、过时代次或断线请求不可再次提交；等待不会自动批准。
- [ ] 本地写入成功仅显示已发送响应，进展事件才表示继续执行；发送窗口断线记录 delivery_unknown，不自动补发批准。
- [ ] 经公开命令、两标签页和 ACP 故障验证响应、取消竞争、失效与未知交付，不依赖内部 CAS 函数断言。

- [ ] 权限卡片与审批表单是公开可替换视图，展示服务端提供的来源、选项和有效状态；所选 UI 调用相同响应命令，无权自行授予权限、延长请求有效期或跳过单次领取／连接代次校验。

规格用户故事：25, 28, 29, 30, 31, 74。

验收共识：遵循正式规格、领域词汇与已接受 ADR（含全界面公开替换契约 ADR-0004）；使用真实 Host、插件和持久化，经浏览器或公开命令/查询/事件及维护入口验证外部行为。ACP 协议替身仅用于外部 Agent 与故障控制，真实 Agent 验收不得被替代。
