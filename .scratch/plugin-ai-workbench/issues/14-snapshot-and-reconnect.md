# 14: 浏览器断线后的状态恢复

**What to build:** 用户刷新、断网或慢连接后恢复已保存的会话状态，时间线不丢失、不重复。

**Blocked by:** 12: 完成文本执行轮次并随时取消

**Status:** resolved

- [x] 公开查询提供一致读快照中的 snapshot、streamId、cursor，WebSocket 从数据库补读后续序号，避免回放与通知交界丢失。
- [x] 序号按十进制字符串传输，客户端只推进已应用 cursor 并按事件 ID 幂等合并；异步投影使用自己的事件或已应用水位。
- [x] Host 新启动更换 streamId，游标过旧、备份恢复或保留窗口失配要求重新同步；不能无限重放所有历史。
- [x] 慢客户端缓存有界，超过范围断开并提示重新连接；未落库内容不能表现为已保存，订阅受身份与 Origin 校验。
- [x] 在公开边界构造快照交界写入、投影落后、连接断开和慢消费者，浏览器恢复结果与持久查询一致。

规格用户故事：3, 35。

验收共识：遵循正式规格、领域词汇与已接受 ADR（含全界面公开替换契约 ADR-0004）；使用真实 Host、插件和持久化，经浏览器或公开命令/查询/事件及维护入口验证外部行为。ACP 协议替身仅用于外部 Agent 与故障控制，真实 Agent 验收不得被替代。

## Answer — 2026-11-16

已与13共同合入 `codex/plugin-ai-workbench`，组合源 `5bb5156`，合并提交 `e4d36f410a29229bbe7d373d03cdbb6e2f28269b`。SDK 提供同步 owner snapshot 与独立、只读、会过期的 ReadSnapshot；同一次 SQLite 读事务取得领域状态及 streamId/cursor，文件系统观察单独标明状态，不宣称跨插件或文件系统的全局原子快照。owner 在领域事务中发布自己的浏览器事件，异步投影不借全局水位跳过未应用内容。

WebSocket 受 Cookie 身份、Origin、当前插件图及 owner/principal 过滤约束，持续从数据库按整数序号补读；线上游标为十进制字符串。每 Host 启动采用新 streamId，旧／未来游标、保留窗口失配及旧备份要求 resync。保留2048个浏览器事件，每条不超过32KiB；每页最多8项并等待应用 ACK，慢消费者有5秒期限及缓存／连接数量限制。浏览器只在一致替换快照成功应用后推进游标，重复事件幂等处理。

独立复核发现并修复数字序号被文本别名按字典序排序、在线状态下的网络失败误清缓存、挂起快照阻止重新同步、默认会话因目录／投影查询失败隐藏已保存内容等问题。公开回归覆盖快照交界、异步投影滞后、超过2^53的序号及过滤间隙、慢客户端与健康客户端并存、重启／旧备份／权限撤销、实际 WebSocket、独立安装 UI、浏览器断线及迟到响应。默认会话保留已保存消息、工具和草稿，显示各自的新鲜度错误，取消仍可使用；真实授权失效仍清除受保护状态，重连不重发输入或自动继续队列。
