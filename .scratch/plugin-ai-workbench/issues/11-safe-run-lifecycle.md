# 11: 准备与结束运行，落实工作区占用

**What to build:** 用户从 Session 启动一个 ACP Run 至 ready，看到版本、目录和能力，再结束运行；重叠目录始终只有一个写入所有者。

**Blocked by:** 06: 配置、启停与恢复插件, 08: 浏览和操作工作区文件, 10: 创建会话并查看历史索引

**Status:** claimed

- [ ] 持有 Host 单实例锁后，原子受理 Workspace Claim、Run 和启动操作；进程启动在提交后，Runtime 不改写 sessions 私有数据；运行事实投影与消费 offset 同事务提交。
- [ ] 通过 ACP 测试进程执行 initialize 与原生会话创建，记录连接代次、版本、受控环境和原生状态引用；不开放 prompt。
- [ ] 真实目录别名及祖先/后代重叠互斥；ready 状态持有 Claim，文件服务的并发写入也遵守同一所有权规则。
- [ ] 结束 Run 先停止受管进程和登记任务，确认后释放；不确定时 blocked 并可诊断，不按 TTL、心跳或旧 PID 擅自释放或杀进程。 不支持原生恢复的 Agent 不自动休眠，用户结束时明确提示下次需要新建原生会话。
- [ ] Host 再启动先封闭旧 Run，暂停派发，未知 Claim 不让位；插件生命周期注册当前使用关系，防止绕过启停门禁。
- [ ] 浏览器可演示启动与结束；公开接口并发测试占用和失败，子进程只获所需环境；界面明确占用不构成 OS 沙箱。

规格用户故事：9, 10, 15, 33, 34, 72。

验收共识：遵循正式规格、领域词汇与已接受 ADR（含全界面公开替换契约 ADR-0004）；使用真实 Host、插件和持久化，经浏览器或公开命令/查询/事件及维护入口验证外部行为。ACP 协议替身仅用于外部 Agent 与故障控制，真实 Agent 验收不得被替代。
