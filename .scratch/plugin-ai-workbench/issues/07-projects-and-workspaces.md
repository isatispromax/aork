# 07: 创建项目与普通目录工作区

**What to build:** 用户创建非 Git Project，登记托管或明确授权的外接目录为 Workspace，刷新后仍能找到稳定身份和真实目录。

**Blocked by:** 03: 访问 Token 与浏览器会话

**Status:** ready-for-agent

- [ ] Project 与 Workspace 分开建模，一个项目可含多个工作区；路径不是 Workspace 身份，外接目录记录访问范围和管理方式。
- [ ] 创建与编辑经过公开命令，身份加 commandId 去重：相同内容返回原回执，不同内容冲突；状态、回执和事件在单库短事务提交。
- [ ] 单 Host 写入口使用 SQLite WAL、外键及既定同步设置；跨边界 schema 校验，事件脱敏并使用可持久化的递增序号。
- [ ] 校验服务器真实目录及访问范围，清楚展示路径；失败不留下半份可见项目或工作区。
- [ ] 浏览器可切换项目和工作区，归档代替级联删除；存在引用时不直接清理其数据。
- [ ] 通过浏览器、公开命令及重启后查询验证幂等、持久化、错误目录和非 Git 目录。

规格用户故事：4, 5, 6, 7, 19。

验收共识：遵循正式规格、领域词汇与已接受 ADR（含全界面公开替换契约 ADR-0004）；使用真实 Host、插件和持久化，经浏览器或公开命令/查询/事件及维护入口验证外部行为。ACP 协议替身仅用于外部 Agent 与故障控制，真实 Agent 验收不得被替代。
