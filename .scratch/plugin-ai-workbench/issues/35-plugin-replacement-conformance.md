# 35: 验证新插件与 Provider 可替换性

**What to build:** 外部作者按公开 SDK 独立打包并安装新的 ACP 测试 Provider 和完整 UI 提供者，工作台无需改 Host 或重建即可替换正常界面；服务端业务行为不变，停用可选能力仍能继续工作。

**Blocked by:** 18: 全局待处理、未读与工作台导航, 28: 完成无 Git 的资料处理工作流, 29: 增加 Git 与 diff 编码工作流, 34: 插件升级、迁移与匹配回退

**Status:** ready-for-agent

- [ ] 在固定 Host 构建之后独立生成额外 Provider 插件，注册、创建 Profile 并通过既有会话工作流完成文本轮次，不改 kernel 或 sessions 主流程。
- [ ] 固定 Host 构建之后独立生成 UI 包，通过真实安装入口和 profile 显式选择，实际替换主布局、composer、审批表单、登录和设置；证据包含独立包／Host 标识、选择配置及浏览器结果，不能以新增面板或原型切外观代替。
- [ ] 对照架构第 11 节逐项验证侧栏、页头、首页、项目／工作区、会话列表／主视图、消息、结构化表单、文件／产物、插件管理、菜单／通知的替换；同时验证导航、面板、命令、附件、renderer、设置分组等扩展的注册／撤销。替换布局后再独立替换 composer 或审批表单，不依赖内部 React 树、DOM 或 Query Context。
- [ ] 多候选、不同安装／注册顺序、重复 ID、缺失目标、UI 契约不兼容和依赖撤销均有确定结果；profile 明确选择提供者，多项扩展能排序／隐藏，主题／token／图标统一，禁止最后注册者胜出。
- [ ] 同一 Session 在替换前后继续使用相同历史、输入受理／队列／取消规则；Interaction 在替换审批表单后仍由公开服务保证一次响应、旧连接失效及 delivery_unknown 语义。登录 UI 替换不绕过身份／CSRF／Origin，设置和界面隐藏不改变服务端权限或能力协商。
- [ ] 共享 React/runtime 运行正常，不重复注册，Plugin 激活或视图失败局部可诊断且可恢复。
- [ ] 停用 Git 后仍能完成已有非编程资料处理，停用业务视图不删除已保存历史；数据访问只经公开所属服务。
- [ ] 重复启停 UI 包无残留订阅、样式或注册；当前提供者渲染失败／失效时有可见错误、显式兼容回退或最小错误兜底，管理 UI 失效可用服务器本地入口恢复。旧图命令拒绝并要求刷新，权限失效后清除受保护缓存／订阅并拒绝操作；纯 UI 停用不自动停止运行或响应请求。
- [ ] 单独使登录或管理 UI 渲染失败时，其他有效登录会话、已授权可用视图及服务器 Run 不被错误失效／终止；未认证请求仍被拒绝。真正的认证／授权服务不可用与单个 UI 故障分别验证。
- [ ] 本票是具体 Plugin 替换工作流的契约验收，不是新的公开市场或长期稳定 SDK 承诺；测试 Provider 不能代替真实 Claude/Codex。
