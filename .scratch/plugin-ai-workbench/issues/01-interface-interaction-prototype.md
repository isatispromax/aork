# 01: 界面交互原型与用户确认

**What to build:** 先交付可在浏览器直接操作的界面交互原型，围绕主要流程和关键状态校验 Aork 工作台交互；收集用户反馈并获得明确确认后，再启动后续功能开发。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 提供独立、可丢弃的浏览器原型，入口为 [prototype/index.html](/Users/yangdi/code/multai/Aork/.scratch/plugin-ai-workbench/prototype/index.html)；仅使用内存状态和示例内容，刷新可重置，不接真实 Agent、后端、数据库或生产凭据。
- [ ] 可以在 Project、Workspace 与 Session 间导航，明确项目、文件环境、会话及运行的不同含义；可以新建会话并选择 Agent Profile，展示实际工作目录及尚未启动状态。
- [ ] 可以模拟发送输入、执行中排队、删除尚未执行的排队输入及显式继续；区分取消当前 Turn 与结束整个 Run，显示取消中、已取消、结束中、已结束等关键状态，不把归档会话当作停止运行。
- [ ] 可以模拟有响应通道的权限请求和结构化输入，演示响应、失效及重复响应受阻；普通问句和一般完成回复不进入待处理，未知或不支持的能力以明确禁用或说明呈现。
- [ ] 可以通过跨项目的全局待处理与未读入口定位会话；待处理交互和未读回复分别计数，阅读、响应后的变化可观察。
- [ ] 右侧提供文件与Git改动tab：文件树/搜索/预览/行号/加入输入，Git来源筛选、文件状态/增删统计和可展开diff；各工作区状态独立，窄屏可返回目录。当前原型不提供资料库或产物管理界面。
- [ ] 可以模拟中断后的恢复和更换 Agent，区分原生会话恢复与带选定上下文的新会话；没有恢复能力时给出清楚的替代路径，模拟状态不代表真实进程或恢复成功。
- [ ] 插件配置归入设置页内部，与Agent配置分区；没有插件独立导航、界面定制页或个人工作台/账号配置入口。任何变更仅影响内存，不声称插件已真实安装。
- [ ] 参考本地codex与ZCode并采用专业设计skill细化导航、会话、输入和文件/Git面板；正确区分Codex CLI/TUI与桌面GUI、ZCode Review与提交历史；检查响应式、对比度与键盘焦点。
- [ ] 保留全部正常UI可插件替换的架构约束，但当前原型不提供独立的界面组合选择器。只在设置中配置插件；外观和内存模拟不能证明正式插件运行时已实现。
- [ ] 原型明显标注演示性质，覆盖主要正常流程及等待、禁用、错误、取消、中断等关键状态；记录用户反馈、取舍与待调整项，完成一次实际浏览器交互检查。
- [ ] 支持浅色、深色与跟随系统；以用户 Codex 截图参考布局，中央结合 dsh 阅读流/紧凑输入，右侧保留 ZCode 文件/Git。主题不改变栏宽和位置，不重置会话与面板状态。
- [ ] 用户查看原型并明确确认交互；在 Comments 追加确认日期、原型版本或路径、确认范围及待处理反馈。只有该确认已发生且反馈已按约定处理，才可完成本票并解除 02–37 的功能开发门禁。

原型边界：本票验证界面结构和交互决策，不实现正式 Host、ACP、持久化、身份认证、进程控制或真实插件装配。模拟动作和浏览器交互检查均不能作为后续功能票完成或真实 Agent 验收的证据。
