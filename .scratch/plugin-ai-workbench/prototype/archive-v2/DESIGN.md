# Aork 原型设计方向：参考整合版

2026-11-15。范围仅为交互原型；用户尚未确认最终交互，功能开发门禁保持关闭。

## 1. Visual Theme & Atmosphere

以 dsh 的会话工作台为主要骨架，采用中性灰白、紧凑导航、宽阅读列和按需面板。优先让用户理解“我在哪里工作、谁在执行、下一步是否需要我回应”。新增 D 作为默认参考整合方案，A/B/C 保留对照。

## 2. Color

白色主内容面，侧栏 #F9FAFB，主文字 #0F1115，次要文字 #60646C，辅助文字 #60646C，边界 #E5E7EB。主要动作使用近黑色，链接或少量选中强调可用蓝色。运行、等待和失败仍用语义状态色，不把绿色铺满导航和主按钮。

## 3. Typography

采用 dsh 同类系统字体栈，中文优先 PingFang SC/Microsoft YaHei。导航 14px/20px，正文 14px/24px，辅助信息不小于 12px/18px，重要说明不以低对比度弱化。大部分字重 400–500，主要层次由位置、字号与墨色表达，避免每个区域都有粗大标题。

## 4. Spacing & Grid

桌面左栏约 280px，项目/工作区/会话用 32px 左右的紧凑树行组织。中央阅读区最大约 800–920px，输入框与消息共轴。保护会话最小可用宽度；右面板只在需要时打开。窄屏侧栏改抽屉，标题保留会话切换入口。

## 5. Layout & Composition

将原 A 的项目栏与会话栏合并为一棵导航树，减少常驻列。顶部显示项目/工作区/会话上下文与当前视图操作。中央保留对话、过程摘要和交互卡。资料与产物共享一个带 tabs 的右侧容器，关闭后完整让出空间。

## 6. Components

所有正常产品界面均由独立 UI 插件经公开契约替换或扩展，涵盖登录、设置、插件管理与消息/审批/输入等子视图。原型只演示组合选择；正式提供者注册、版本、profile 选择与服务端授权按 ADR-0004 实施。

按钮和导航行约 R8–12，独立内容卡 R20，输入框与对话框 R28；这些层级参考 dsh，非逐像素复制。用户消息右对齐，助手正文保持阅读流；工具过程归为可展开的小摘要。输入卡包含附件、Agent/模型与发送，环境信息放在卡片下方。产物在消息内以紧凑入口出现，打开面板后可预览与下载，并加入后续输入。

## 7. Motion & Interaction

切换会话和 tabs 即时响应，辅助转场 100–200ms；尊重减少动画设置。保留已有队列、取消、目录占用、请求有效性和上下文交接行为。折叠只改变呈现，不能隐藏仍需响应的权限/表单。更换 Agent 创建关联会话，不静默替换现有 Run。

## 8. Voice & Brand

使用 Aork 自己的品牌与中文术语。按钮描述动作，状态区分“已发送响应”“执行中”“本轮已停止”“运行已结束”。显著保留原型/示例标识，不把模拟行为称为真实 Agent 能力。公开参考资料只作设计证据。

## 9. Anti-patterns

不复制 dsh/AionUi 等品牌、徽标或宣传承诺；不增加 Task/Teams/IM/自动编排领域对象；不默认展示多列设置与日志；不把每次工具调用做成独立大卡；不以模型选择代替 Agent Profile；不把旧版截图当当前实现，不把浏览官方文档当实机验收。A/B/C 的旧交互保留用于比较。
