# Aork：以外部 ACP Agent 为执行主体的插件化 AI 工作台

Status: ready-for-agent
日期：2026-11-15
范围：首版个人远程通用工作台

本规格整合已有产品设计、技术架构基线和已接受 ADR。用户已确认本文的测试边界并授权发布；`ready-for-agent` 表示需求已整理可供实施，不表示功能已实现、依赖兼容性已验证或产品已交付。当前执行顺序受工单 01 的用户交互确认门禁约束，用户确认前不得开始 02–37 的功能开发。

## Problem Statement

用户希望从浏览器持续开展编程、研究、文档和文件处理工作，由 Claude、Codex 等 Agent 在服务器上实际执行。工作需要有明确的文件环境、可持续的会话、可处理的权限或信息请求，以及可查看、下载和再次使用的产物；不能把 Git 仓库作为所有工作的前提。

单独运行 Agent CLI 难以提供统一的远程项目组织、跨会话待处理入口、浏览器断线后的状态恢复和插件扩展。将工作台本身做成另一个主 Agent，又会混淆推理、工具执行与会话历史的所有权。用户需要一个管理工作环境和交互的宿主，让外部 Agent 保持执行主体身份，同时清楚呈现哪些工作仍在运行、哪些请求仍可响应、哪些输入的交付结果已经无法确定。

插件化必须体现为可独立安装和替换的能力包。只有静态界面或聊天演示，不能满足完整工作台的要求。

## Solution

交付一个部署在单台 Linux 服务器上的单用户 Aork 工作台。用户通过浏览器登录，创建 Project 和 Workspace，选择 Agent Profile，开始 Session，发送输入并查看流式结果，在全局入口处理有效 Interaction，最后查看和复用 Artifact。Agent、凭据、原生历史和工作文件留在服务器；关闭浏览器不终止服务器上的执行。

所有用户可见业务由默认 Plugin 组合提供，包括工作台界面、认证、项目与工作区、会话、交互、Agent 接入、工具和产物。内核只保留插件运行、资源管理、存储与权限强制入口等机制。外部 Agent 通过 ACP 接入，自行负责推理和工具循环；Aork 工具通过受运行授权约束的 MCP 桥接提供。

所有正常产品界面都能经独立 Plugin 替换、扩展和主题定制，包括整体布局和登录页；插件能力不限于增加侧边面板。默认界面与外部界面使用同一套版本化公开 UI 契约。宿主仅提供加载、权限强制及插件不可用时的最小启动／错误兜底，不把正常业务界面硬编码进不可替换 Shell；界面替换也不能改变服务端的认证、运行、工作区占用或 Interaction 规则。

首版同时验证 Claude 和 Codex 的真实远程工作流程，并完成一个非编程资料处理场景和一个编码场景。浏览器重连、中断、取消、原生恢复、插件升级与工作区占用都必须有可解释的用户可见结果；不能以协议替身通过代替真实 Agent 验收。

## User Stories

以下按“作为某个角色，我希望获得某项能力，以便获得某项收益”的格式描述可验收的用户需求。

1. 作为工作台用户，我希望通过浏览器登录服务器上的 Aork，以便在自己的设备上访问同一套工作环境。
2. 作为工作台用户，我希望 Agent、凭据和工作文件留在服务器，以便浏览器只负责交互和展示。
3. 作为工作台用户，我希望关闭浏览器后服务器上的执行继续，以便离开页面不会丢失正在进行的工作。
4. 作为工作台用户，我希望创建不依赖 Git 的 Project，以便组织研究、文档和其他持续工作。
5. 作为工作台用户，我希望一个 Project 可以包含多个 Workspace、Session 和 Artifact，以便把相关工作放在同一组织容器中。
6. 作为工作台用户，我希望选择托管目录或明确授权的外接目录作为 Workspace，以便使用已有资料或新的工作环境。
7. 作为工作台用户，我希望 Workspace 有稳定身份并显示实际服务器目录，以便明确每次执行使用哪些文件。
8. 作为工作台用户，我希望在界面中浏览和操作获准的工作区文件，以便准备输入和检查工作结果。
9. 作为工作台用户，我希望为并行执行选择独立 Workspace，以便避免多个 Agent 同时修改重叠目录。
10. 作为工作台用户，我希望在工作区仍被运行占用时看到占用原因，以便知道何时可以安全开始其他写入工作。
11. 作为工作台用户，我希望分别管理 Claude、Codex 等 Agent Provider 的接入状态，以便选择实际可用的 Agent。
12. 作为工作台用户，我希望保存 Agent Profile 的参数和凭据引用，以便重复使用已配置的接入方式。
13. 作为工作台用户，我希望通过 Provider 支持的远程认证流程完成登录，以便不依赖浏览器与服务器处于同一台机器。
14. 作为工作台用户，我希望创建 Session 时选择 Workspace、Agent Profile 和工具集，以便明确该会话的执行环境。
15. 作为工作台用户，我希望查看会话使用的 Agent、工作目录、版本和运行状态，以便判断工作正在何处执行。
16. 作为工作台用户，我希望在同一 Session 中持续多轮交流，以便围绕同一项工作逐步推进。
17. 作为工作台用户，我希望看到流式回答和 Agent 报告的工具状态，以便了解已经发生的执行进展。
18. 作为工作台用户，我希望运行中的后续输入明确进入队列，以便不把多条输入误认为同时交付给 Agent。
19. 作为工作台用户，我希望重复点击或网络重试不会重复创建 Session 或 Turn，以便避免重复工作和副作用。
20. 作为工作台用户，我希望区分输入已受理、正在执行和已完成，以便不把命令回执误认为执行成功。
21. 作为工作台用户，我希望输入交付结果不确定时得到明确提示，以便自行判断后续动作而不是被自动重发。
22. 作为工作台用户，我希望只看到 Agent 实际支持的附件、模型、模式和配置选项，以便不提交无法执行的请求。
23. 作为工作台用户，我希望费用、用量和内部执行信息缺失时显示未知，以便不会把推测当成真实运行数据。
24. 作为工作台用户，我希望在跨项目入口查看仍然有效的 Interaction，以便及时处理阻塞执行的权限或结构化输入请求。
25. 作为工作台用户，我希望权限请求等待我明确选择，以便不会因超时或未读而自动批准。
26. 作为工作台用户，我希望按协商能力使用结构化表单，以便完整提供 Agent 需要的信息。
27. 作为工作台用户，我希望普通问句和已完成回答不被当成有效 Interaction，以便待处理列表反映真实响应通道。
28. 作为工作台用户，我希望多个标签页只能成功响应同一请求一次，以便避免冲突或重复批准。
29. 作为工作台用户，我希望失效连接上的旧请求不能继续提交，以便不会误以为历史卡片仍能控制 Agent。
30. 作为工作台用户，我希望区分响应已发送与 Agent 已继续执行，以便准确理解审批后的状态。
31. 作为工作台用户，我希望随时取消当前 Turn，以便长时间执行或等待权限时仍能停止工作。
32. 作为工作台用户，我希望取消中和取消完成明确区分，以便知道 Agent 是否已经停止本轮工作。
33. 作为工作台用户，我希望结束或休眠 Run 后才释放工作区占用，以便仍存活的运行不会与后续工作争抢目录。
34. 作为工作台用户，我希望无法确认停止时工作区保持受阻并提供诊断，以便不会在未知进程仍可能写入时继续执行。
35. 作为工作台用户，我希望刷新或断网重连后获取已保存的当前状态，以便继续查看工作且不丢失或重复显示内容。
36. 作为工作台用户，我希望 Agent 或 adapter 崩溃后保留已收到的内容和文件，并显示中断，以便理解已经完成与尚未完成的部分。
37. 作为工作台用户，我希望服务重启后旧 Interaction 失效、活动工作如实标记中断或交付不确定，以便不会误操作已消失的连接。
38. 作为工作台用户，我希望服务重启后队列保持暂停，直到我明确继续，以便恢复连接不会自动启动旧输入。
39. 作为工作台用户，我希望仅在 Provider 支持且原生状态可用时恢复原 Session，以便恢复能力与实际接入条件一致。
40. 作为工作台用户，我希望恢复原生历史时保留工作台输入、交互结果、中断记录和产物关联，以便已有工作记录不会消失。
41. 作为工作台用户，我希望无法恢复的历史仍可查看，并能建立关联的新 Session，以便在不伪造原生恢复的情况下继续工作。
42. 作为工作台用户，我希望换 Agent 时创建关联的新 Session，并选择携带文件、摘要或产物，以便明确发生了上下文交接。
43. 作为工作台用户，我希望未读回复与待处理请求分开显示，并在打开对应内容后清除未读，以便分别管理阅读和行动。
44. 作为工作台用户，我希望会话工具集可见且新安装工具不会自动加入运行中的环境，以便知道 Agent 实际获准使用哪些能力。
45. 作为工作台用户，我希望 Agent 能调用选定的工作台工具，并看到真实的失败结果，以便工具故障不会被伪装成成功。
46. 作为工作台用户，我希望运行结束后对应工具授权失效，以便旧连接不能继续执行已撤销的操作。
47. 作为工作台用户，我希望通过显式登记或确认把结果保存为 Artifact，以便不会把工作目录中所有文件都归为 Agent 产出。
48. 作为工作台用户，我希望 Artifact 记录版本、来源 Session 和 Turn，以便追溯结果并引用明确版本。
49. 作为工作台用户，我希望预览和下载已登记产物，未知格式也能获得文件信息，以便使用不同插件生成的结果。
50. 作为工作台用户，我希望把产物再次交给 Agent 作为上下文，以便继续处理已有结果。
51. 作为工作台用户，我希望生成的 HTML 等主动内容在受限环境预览，以便预览内容无法使用工作台登录凭据。
52. 作为工作台用户，我希望无需 Git 就能完成资料读取、带来源摘要或文档生成、预览、下载和再次使用，以便验证通用工作能力。
53. 作为工作台用户，我希望安装编码插件后获得 Git、diff 等对应能力，以便编码工作也沿用同一套工作区和会话流程。
54. 作为工作台用户，我希望通过导航、主视图和上下文／产物面板完成主要流程，以便在会话与结果之间切换。
55. 作为工作台用户，我希望可选插件视图失败时看到局部错误和恢复入口，以便单个视图故障不会掩盖已保存的工作。
56. 作为工作台维护者，我希望查看插件清单、配置、依赖、启停状态和诊断，以便管理当前工作台能力。
57. 作为工作台维护者，我希望从服务器安装独立预构建插件而无需修改 Host 源码或重建工作台，以便扩展能力。
58. 作为工作台维护者，我希望不兼容的 SDK、依赖、配置或插件产物在激活前被拒绝，以便定位具体安装问题。
59. 作为工作台维护者，我希望插件停用或激活失败时释放其注册资源，以便反复启停不会留下重复入口或监听器。
60. 作为工作台维护者，我希望停用能力不自动删除其历史数据，以便以后恢复插件或查看已有工作。
61. 作为工作台维护者，我希望安装和升级先停止全部受影响运行，并在 Host 重启前停止全部 Run，以便维护过程具有明确边界。
62. 作为工作台用户，我希望升级后旧页面被要求刷新，以便不会用旧界面向新插件图提交不兼容命令。
63. 作为工作台维护者，我希望迁移失败时回退匹配的插件版本和数据，以便恢复一致状态。
64. 作为工作台维护者，我希望备份覆盖数据库、原生状态、插件配置、托管工作区和产物，以便恢复完整的工作环境。
65. 作为工作台维护者，我希望外接目录在备份中明确标为外部依赖，恢复时校验映射和内容，以便不会被静默复制、覆盖或误用。
66. 作为工作台维护者，我希望通过服务器本地命令初始化账号和修复认证故障，以便公网不会出现匿名管理入口。
67. 作为工作台用户，我希望浏览器、日志和事件流不包含已有服务器凭据或认证载荷，以便凭据保持在服务器的受限范围内。
68. 作为插件作者，我希望通过版本化 Aork SDK 注册服务、工具和界面贡献点，以便不依赖宿主内部框架。
69. 作为插件作者，我希望一个 Plugin 可以同时提供服务端和浏览器能力，以便把紧密相关的能力独立交付。
70. 作为 Agent Provider 作者，我希望增加新的 ACP Agent 时无需修改内核或会话主流程，以便复用已有运行和交互机制。
71. 作为工作台维护者，我希望记录真实 Agent、adapter、SDK、Node 和操作系统的验证版本，以便区分实际兼容性与协议声明。
72. 作为工作台用户，我希望清楚知道首版采用可信插件和 Agent 的单用户环境，以便不会把工作区占用或插件能力声明误认为系统安全沙箱。
73. 作为工作台用户，我希望通过插件替换整体布局、侧栏、页头、首页、项目工作区和会话列表，以便按自己的工作方式组织完整工作台。
74. 作为工作台用户，我希望通过插件替换输入区、消息、权限和结构化表单、文件与产物界面，以便定制工作交互，同时保留相同的会话、运行和响应语义。
75. 作为工作台用户，我希望登录、设置、插件管理、菜单和通知也能通过插件定制，以便完整产品不会留下只能修改宿主源码才能调整的业务界面。
76. 作为工作台维护者，我希望显式选择每个界面的提供者并排序或隐藏扩展贡献，以便多个插件共存时结果确定，不因安装或注册顺序意外改变界面。
77. 作为插件作者，我希望通过版本化公开 UI 契约及统一主题、token 和图标接口交付独立界面包，以便无需修改宿主源码或依赖内部组件树即可定制全部正常界面。
78. 作为工作台用户，我希望界面插件停用、依赖失效或加载出错时能看到原因并恢复到明确选定的可用组合，以便已保存数据和服务器执行不因界面故障消失，也不会继续使用失效权限或旧页面操作。

## Implementation Decisions

### 产品与领域边界

- 首版为单台 Linux 服务器、单一工作台用户、可信已安装 Plugin 和本机 Runner。macOS 可用于开发，Linux 部署和进程清理单独验收。
- 按领域词汇区分 Project、Workspace、Agent Provider、Agent Profile、Session、Runtime Run、Turn、Interaction、Workspace Claim 和 Artifact。Session 是持续对话，Run 是一次实际运行，Turn 是一条已受理输入的工作单元；首版不建立独立 Task 领域对象。
- Workspace 使用稳定身份、Runner 和真实目录访问范围。Project 不等同于 Git 仓库，Artifact 不等同于目录中的任意文件。
- 外部 Agent 拥有推理、上下文压缩、工具选择和原生历史。Aork 管理环境、运行与交互，不包含主 Agent 循环，也不承诺自己的聊天记录可还原 Agent 内部上下文。

### 技术基线与模块职责

- 采用 TypeScript strict、ESM、pnpm workspace、Node.js 24、Fastify 5、React 19 与 Vite；SQLite WAL、better-sqlite3 与 Drizzle 负责本机持久化。上述版本是已有架构选择，精确依赖组合在首次工程落地时锁定并验证。
- 使用 `@deepseek-ai/cordis` 4.1.0 的私有适配层实现生命周期与依赖注入。公开 Plugin 只依赖 Aork SDK 和所需业务契约，不接触 Cordis、Fastify 或数据库驱动内部接口。
- 内核负责插件图、生命周期、资源回收、版本与依赖检查、权限强制入口及最小受保护恢复机制；不拥有项目、会话、文件树、Git 或模型业务。
- 默认组合包含单用户认证、workbench、workspace、sessions、interactions、本机 runner、runtime-acp、Claude／Codex provider、tools-mcp 和 artifacts；研究／文档及编码能力通过附加插件验证。
- workspace 拥有 Project、Workspace 和 Workspace Claim；sessions 拥有 Session、Run、Turn 和时间线；interactions 拥有有效请求及响应投影；runtime-acp 拥有运行操作队列、活连接、进程及 RPC 句柄，并发布运行事实；artifacts 拥有产物版本与引用。
- sessions 调用 workspace 与 Runtime，interactions 调用 Runtime，Runtime 调用 Runner 和 Provider 注册表。Runtime 不反向修改 Session 或 Interaction 的私有表；事实消费者更新自己的状态，并同事务提交消费进度。
- 独立业务契约按服务和主版本管理；内核不依赖业务实现，插件不导入其他插件内部源码。耗时计算、转换与外部程序不得阻塞 Host 事件循环。

### Plugin 安装、运行与升级

- 清单声明稳定 ID、版本、SDK 范围、server／client 入口、静态资源、必需及可选依赖、服务、贡献点、配置约束、申请能力和迁移版本。静态清单校验完成后才导入代码；入口和资源不能越出插件包或指向任意外部地址。
- Plugin 交付独立预构建 ESM 和显式静态资源。首版通过服务器 CLI 安装本地归档，无需修改 Host 源码或重新编译整个工作台。浏览器插件管理提供清单、配置、启停和诊断。
- 生命周期涵盖发现、校验、依赖解析、激活、停止接单、资源释放与停用。路由注册、监听、UI 贡献和进程引用归属激活作用域；激活中途失败也执行清理。
- 浏览器通过当前插件图生成的引导清单加载同源内容哈希资产；共享 React、React DOM 及 Aork 客户端／UI runtime 的受支持入口，拒绝重复 React 和未知共享依赖。宿主查询缓存通过 SDK 暴露，不将内部 Query Context 变成公共契约。
- 安装和升级执行兼容检查、停止全部 Run、一致备份、迁移、Host 重启与页面刷新。仅不需重启的现有插件启停可限制影响范围；依赖中的服务需先排空受影响运行。首版不同时托管多个版本。
- Host 提供启动代次、插件图版本和 API 版本；旧页面提交过时图版本时返回刷新要求。运行保存 Provider、adapter、配置及原生状态引用，新增工具或升级不得静默改变运行环境。
- 迁移按依赖顺序由 Host 执行并记录版本和校验和。失败恢复旧插件及匹配数据；停用不等于删除历史，旧版本无法运行且恢复兼容性未验证时历史只读。

### 全界面插件契约

- 正常产品界面全部由 Plugin 提供：整体布局、侧栏、页头、首页、项目／工作区页面、会话列表与会话视图、输入区、消息、权限卡片与结构化表单、文件浏览／编辑、产物预览、登录、设置、插件管理、菜单和通知。默认实现也通过公开 UI 契约装配，不享有内部入口特权。
- 公开契约区分**独占视图提供者**和**多项扩展贡献**。每个可替换界面有稳定 ID、契约主版本、公开数据／命令接口和加载／空白／错误状态；发行组合（Distribution Profile，简称 profile，不同于 Agent Profile）显式选择唯一 `pluginId:providerId`。组合布局必须继续经公开子视图契约装配输入区、表单等子界面，不能把它们固化为私有子树。
- 导航项、菜单项、工具栏操作、附件入口、设置分组和通知来源可由多个插件贡献，由 profile 保存顺序及显隐，稳定 ID 用于相同顺序下的确定性排序。renderer 的同类型候选同样显式选择。缺失选择、重复 ID、目标不存在和不兼容候选给出诊断；禁止以最后注册者覆盖前者。
- 清单声明 UI 契约版本、提供者、扩展目标、服务依赖和所需权限，激活前校验；布局替换不赋予访问额外数据的权限。UI 只消费公开查询／事件和 commands，领域存储、密钥与进程仍由对应服务负责，客户端不可越过服务端授权、能力协商、幂等、Workspace Claim、Interaction 单次响应或连接代次检查。
- 主题插件通过版本化 token 与图标接口统一颜色、字体、间距和图标；共享基础组件是可复用工具，不是不可替换的业务页面。主题和视图样式有命名空间，不依赖私有 DOM 选择器、任意拦截内部 React 树、Query Context 或 monkey patch。
- UI 注册、订阅、监听、样式和临时资源归属可撤销作用域；依赖撤销、停用和激活失败必须清理。UI 组合纳入插件图版本，旧页面操作收到刷新要求；刷新后重查身份、能力和数据。认证失效时清除受保护的缓存／订阅并拒绝后续操作，不只隐藏按钮。
- 视图故障提供可定位的局部错误，根布局故障进入最小启动／错误兜底。可恢复到 profile 已显式指定且兼容的替代提供者，不能静默选择任意已安装插件。认证／授权服务能力缺失时拒绝业务访问；仅登录 UI 故障时，未认证用户仍不能绕过认证，但不因此撤销其他有效登录会话。仅管理 UI 故障不阻断其他已认证可用视图或服务器运行，可经本地维护入口修复。宿主兜底不能演变为另一套固定登录、设置或工作台业务界面。
- 只撤销 UI 不删除 Session、Interaction、文件或历史，也不自动停止 Run、批准请求或重发输入；包含服务变更时仍遵守排空与维护规则。首版同源可信 UI Plugin 有页面权限，契约与错误边界不构成恶意插件沙箱。

### 公共命令、数据与事件契约

- 浏览器命令、查询和上传下载使用 Aork HTTP 协议；WebSocket 负责事件订阅。取消、批准和输入回复也是 HTTP 命令。浏览器不直接连接 ACP 或持有 Agent 进程。
- 固定入口按注册表分发命令和查询，避免业务 Plugin 生命周期依赖 HTTP 路由热移除。跨边界载荷通过 Zod 等运行时 schema 校验，并在服务端检查已认证身份和能力。
- 命令携带唯一 commandId、版本、载荷及页面插件图版本。身份与 commandId 组合唯一；相同 ID、相同内容返回原回执，不同内容返回冲突。异步受理返回稳定实体标识，不声称 Agent 已执行。
- 单个本地 SQLite 数据库使用 WAL、外键约束、明确 busy timeout 和关键写入 FULL 同步策略。一个 Host 持有唯一常规写入口；数据库不放在网络共享文件系统，Agent、桥接进程和 Plugin 不另开写连接。
- 逻辑数据涵盖命令回执、事件、消费进度、迁移与配置，以及用户登录、项目工作区占用、会话运行轮次与历史投影、运行操作、交互和产物版本。表由所属服务维护；AgentBinding 仅为关联关系，由 Session 原生引用与 Run 连接代次表达，不另设表。
- 领域状态、命令回执和相应持久化事件在短同步事务中提交；跨插件原子操作通过明确的事务参与接口完成，各服务只能访问自己的数据。事务内不执行网络、文件 I/O、进程启动或异步等待。
- 输入受理先保存 queued Turn、用户消息及回执，再经调度事务入运行操作队列。外部副作用在提交之后发起；领域表为权威状态，事件用于通知、恢复订阅和重复消费，不要求重放全部事件才能启动。
- 内部运行事实与浏览器投影事件分开，事件保留来源、关联和版本，序号在线上用十进制字符串编码。原始 RPC、认证载荷和凭据不进入浏览器事件流；诊断有脱敏、保留期和大小限制，大文件通过引用传递。
- 项目和会话删除先归档，由所有者检查引用后清理，不默认跨插件级联删除。

### ACP、运行操作与 Interaction

- runtime-acp 是唯一直接使用 ACP SDK 的模块，以稳定 ACP v1 行为和服务器 stdio 连接为基线。Claude／Codex 使用对应 adapter；Provider 注册检测、固定启动描述、受控环境、认证方式、状态与凭据引用、能力差异及兼容范围。浏览器不能提交任意启动命令。
- 每个活动 Session 默认独占一组 adapter／Agent 进程；一个 Session 只有一个运行所有者，同一时刻最多一个执行中的 prompt Turn，后续输入排队，不依赖 Provider 专有 steering。
- 创建或恢复 Run 先取得 Workspace Claim、启动并 initialize，记录协商能力，再认证和创建或加载原生会话。未协商能力视为不支持；模型、模式、附件、结构化输入、文件／终端 Client 能力分别按实际支持开放。
- 工具调用更新是 Agent 的报告，不触发 Aork 再执行一次工具。未知扩展只提供受控诊断和安全占位；没有真实事件的费用、用量或内部子代理信息显示未知。
- Runtime 操作绑定 operationId、runId 和 generation，并按需关联 Turn／Interaction。每个 Run 串行领取和发起操作，但等待 prompt 结果不能阻塞取消或交互响应。
- 持久化操作区分 pending、attempting、completed、failed 和 delivery_unknown。发往 stdio 前记录 attempting；崩溃后已经尝试且缺少确定结果的非幂等操作不得自动重发。写入本机连接不等于 Agent 已接收或执行成功。
- Session 保留 open／archived 与持久 dispatchPaused；Run 区分 planned、starting、ready、stopping、terminated 和 unknown；Turn 区分 queued、dispatching、running、cancelling、finished，并单独记录完成、取消、错误、中断或交付不确定的结果及原始停止原因。
- Interaction 区分 pending、responding、responded、expired、cancelled 和 delivery_unknown。响应先原子领取，再由 Runtime 校验 Run、连接代次及活 RPC 句柄；旧卡片不能跨连接恢复。responded 仅表示有效本地连接完成响应写入，界面显示“已发送响应”。
- 取消先关闭后续交互响应通道，再发起协议取消；显示取消中直至收到终止结果，必要时按超时策略终止受管进程并记录原因。已经发出的批准、文件修改或外部副作用不承诺回滚。

### Workspace Claim、重连与原生恢复

- Workspace Claim 持有人为 Run，状态为 held、blocked 或 released。冲突按真实目录身份及祖先／后代重叠判断，不能只按 Workspace ID 加锁；Aork 文件写入和 MCP 工具也服从占用规则。
- 停止 Turn 与释放 Workspace 是两个动作。Run 仍存活、等待输入、取消中、受管工具未结束或进程身份未知时保留占用；结束或休眠 Run、撤销工具授权并确认相关写入停止后才释放。TTL 或心跳过期不能证明停止。
- 不支持原生恢复的 Agent 不自动休眠；用户结束时明确提示下一次需要新建原生会话。单个 Run 用进程组和登记句柄监督，无法确认清理时保持 blocked 并提供诊断，必要时通过受控服务重启处理。
- 浏览器读取受授权的 snapshot、streamId 与 cursor，再订阅 cursor 后的事件；状态和 cursor 在一致读快照内取得，订阅从数据库序号补读，避免历史补发与实时通知交界丢失。
- 浏览器只推进成功应用的 cursor，按事件 ID 幂等应用。每次 Host 启动生成新 streamId，保留窗口或恢复备份导致游标不匹配时要求重新同步；异步投影产生自己的事件或暴露已应用水位，不用全局最大序号跳过未追上的数据。
- 消息在有界批次落库后推送，生命周期和权限事件及时持久化；慢客户端超过有界缓存时要求重连。关键事件无法落库时停止接单并终止或阻断受影响运行，不把易失内容显示为已保存。
- Host 重启先持有单实例锁并暂停调度，将存在未完成或排队输入的 Session 持久化暂停，核对旧进程身份、清理、标记中断或交付不确定、失效旧 Interaction，确认后释放占用。不能仅凭历史 PID 杀进程。
- 用户恢复会话创建新 Run 并重新协商能力，只有 Provider 支持且原生状态可用才执行原生加载。历史回放成功后原子切换 Agent 历史投影；失败保留旧版。工作台受理输入、交互、队列、中断及产物记录独立保留。
- 可靠原生标识用于合并回放历史；无法可靠匹配时单独分组，不按文本猜测去重。回放不执行工具、不重复登记产物或发送未读通知。恢复连接不自动重发最后输入或清除 dispatchPaused，只有用户“继续队列”才恢复派发。
- 换 Provider 或无法原生恢复时创建关联新 Session，可由用户选择携带摘要、文件或产物，不跨 Provider 使用原生会话 ID。

### MCP 工具、Artifact 与浏览器体验

- 每个 Run 使用独立 stdio MCP bridge，由 Agent 按 Host 生成配置启动，通过受保护的本机 Unix socket 调用已授权工具。短期令牌绑定真实运行及范围，不信任 Agent 自填 Session ID；Run 结束或授权撤销时失效，进行中的工具需支持取消或继续保持占用受阻。
- 工具、资源和指导性配置分别建模。工具集在会话中明确可见，新安装能力默认不加入现有运行；不假定 Claude 和 Codex 的原生 Skill 或插件格式互通。
- Artifact 显式登记，版本指向不可变内容或明确的外部引用，并关联来源 Session／Turn。可变工作区文件与导出产物版本分别表示；文件先经临时写入、完整校验和原子改名，再登记数据库，登记失败的孤立内容由清理器回收，不宣称文件系统与 SQLite 是一个原子事务。
- 预览按 MIME 与已安装 renderer 选择，未知格式提供信息和下载。HTML 等主动内容使用不带同源权限的受限 iframe；复杂交互预览需独立来源和专门协议，不共享带工作台登录态的来源。
- 浏览器最小 Shell 只提供引导、共享依赖、插件加载与最小失败兜底；登录页属于认证 UI 插件，workbench Plugin 提供默认布局、偏好与导航。全部业务视图按上述公开 UI 契约可替换和扩展；不开放任意拦截内部 React 树或私有状态。
- 默认布局采用项目／会话与待处理导航、当前会话或插件主页面、上下文／产物面板；终端、diff 等按安装能力出现。URL 保存可恢复的页面与实体选择，布局偏好由 workbench 管理。
- 查询缓存可重新获取，当前时间线按有序事件更新，不使用前端计时器推测运行完成。Plugin 视图使用独立错误边界和命名空间样式；共享设计 token。
- 待处理数量来自 interactions 的有效请求投影，普通回复完成产生未读，用户打开对应内容后推进已读游标并清除对应未读标记；不在 Session 再维护另一套等待状态。

### 部署、凭据与维护

- Linux glibc 为正式服务器环境，Caddy 提供公网 HTTPS，Host 监听本机接口，systemd 以专用非 root 用户管理服务。数据库、本机 IPC 和 Agent stdio 不向公网开放。
- 服务器 CLI 建立初始账号，密码采用参数化 scrypt 哈希；服务端持有登录会话，浏览器使用 Secure、HttpOnly、SameSite Cookie。状态变更验证 CSRF，WebSocket 握手验证 Origin，登录有速率限制；认证故障时拒绝公共访问并通过本地恢复入口修复。
- Credential broker 以引用和必要注入提供凭据。手动 API 凭据加密落盘、主密钥独立配置；Agent 原生 OAuth 状态保存在受限目录，不声称所有原生文件均由 Aork 加密。子进程只获得需要的受控环境，浏览器和诊断不泄露已有凭据。
- 单用户、同系统用户下的可信 Plugin 和 Agent 不构成恶意代码沙箱，Agent 原生工具也不保证经过 Aork 权限入口。Workspace Claim 协调受管写入，不能阻止外部手动操作或保证追踪所有脱离管理的原生后台进程。
- 服务整体停止使用控制组清理其进程；单个 Run 的管理仍受上述监督边界约束，不承诺服务重启后的进程无缝接管或单 Run 容器隔离。
- 一致备份先停止新命令、排空并停止全部 Run，确认写入停止，使用 SQLite backup 接口，并保存原生历史、精确插件／配置版本、托管 Workspace 和 Artifact。外接目录登记路径映射、访问范围、内容校验信息及未纳入备份标记，不静默复制或覆盖。
- 恢复验证整批版本、文件引用和工作目录；目录缺失、映射变化或内容不匹配时禁止自动启动，要求用户明确修复或使用当前目录重新开始。仅恢复数据库不能被宣称为完整原生续聊恢复。

## Testing Decisions

- **已确认的主要边界：**通过完整浏览器工作流验收产品，测试经过真实 Host、Plugin、存储和事件通路。并发、故障与持久化测试使用同一套公开 HTTP 命令／查询和 WebSocket 接口；只在外部 Agent 的 ACP 协议边界使用可控替身制造响应、等待、断线和进程退出。无需为每个业务模块新增测试入口。
- **独立验收边界：**通过服务器公开安装／维护入口和实际浏览器加载验收预构建 Plugin，通过选定 Linux 服务器上的真实 Claude／Codex 验收接入能力。系统重启、进程清理、磁盘或存储故障使用测试环境的生命周期与故障条件，不依赖产品专用后门。
- **好测试的标准：**验证用户或调用方可观察的状态、返回值、事件、文件结果及可继续的操作；避免断言内部函数调用顺序、私有表布局、Cordis 对象或特定组件树。真实时间线不得以固定等待时间代替状态条件；不以替身完成、静态截图或单次构建成功证明产品完整交付。
- **测试覆盖模块：**主工作流覆盖认证、workbench、workspace、sessions、interactions、runtime-acp、tools-mcp 与 artifacts 的组合行为；插件分发验收覆盖内核、SDK、构建和加载；真实接入覆盖本机 Runner、两个 Provider 与部署维护。
- **既有依据：**当前只有设计文档与使用内存示例的可丢弃交互原型，没有正式应用实现。原型浏览器检查不证明真实 Plugin 装配或任何产品能力完成。复用技术架构基线中的“插件机制、持久化机制、运行机制、真实接入、插件可替换”五类验收门槛，不将其称作已经通过的测试。采用既定 Vitest、Playwright、协议替身与真实接入测试组合，精确工具版本在实施时锁定。
- **全界面替换验收：**固定 Host 构建后独立打包 UI 插件，经公开安装入口和 profile 选择，实际替换主布局、输入区、审批表单、登录及设置；逐项覆盖全部 UI 契约的替换／扩展／主题定制。替换前后通过同一公开服务验证 Session 和 Interaction 行为，停用、冲突、不兼容、依赖撤销、失效页面及权限变更均有可观察结果。不得以原型中的外观切换或新增一个面板冒充此验收。

## Out of Scope

- 多用户、多租户、不可信第三方 Plugin 或 Agent 的安全沙箱，以及针对任意同系统用户恶意代码的隔离保证。
- 分布式 Runner、多机并发写入、独立 session daemon、通用分布式事件溯源平台和 Kubernetes 等集群编排。
- Aork 自有主 Agent 推理循环、模型供应商抽象主导外部 Agent，以及把内部工具报告重新当作待执行指令。
- 首版独立 Task 对象、自动多 Agent 总控、长期计划调度和持久后台任务。
- 公开插件市场、购买流程、浏览器上传任意可执行包、启动时跟随 latest、同宿主多版本托管、运行中 adapter 热替换及无停机安装升级。
- 跨 Agent 无损迁移上下文、将工作台日志当作原生 Agent 内存、对不支持的能力伪造恢复或结构化输入。
- 未经协商和验证的 ACP v2 Draft／扩展、HTTP MCP 和任意原生 Skill 格式互通承诺。
- 服务重启后无缝接管旧进程、自动重发交付不确定输入、自动批准 Interaction、自动继续重启前队列，或取消时回滚已经发生的副作用。
- 对 Agent 自行脱离管理的全部后台进程进行单 Run 级可靠回收，以及阻止外部手动写入目录的系统级保证。
- 将全部工作区文件自动认定为 Agent 产物，或静默复制、覆盖外接目录以充当完整备份。
- 任意 monkey patch 宿主内部组件树或 DOM、公开底层 Cordis／Fastify／数据库内部接口，以及强迫每个 Plugin 独立部署为微服务。通过公开契约替换全部正常业务视图属于本轮范围，不能用此限制缩减为只增加面板。
- 本次全界面契约更新不解除原型交互确认门禁，不初始化正式应用代码、不安装运行依赖、不部署服务，也不宣称插件机制测试或真实接入已经完成。
